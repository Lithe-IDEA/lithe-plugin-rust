0.1.1 补上 Rust 常用的 rust-analyzer 选项，并给 Rust 的两个设置页加上插件自己画的预览，改设置时直接看到效果。这是正式版本。

功能：
- 新增三个设置：展开过程宏、运行构建脚本、高亮文档注释中的代码，默认都开启。前两项在语言服务器下次启动时生效，高亮文档注释中的代码和原有的保存时检查一样立即生效。
- 「设置 › 语言 › Rust」顶部列出 cargo、rust-analyzer 和 rustup 的版本和路径，点一行到「工具链」页选择其他版本或位置。下面四张预览卡片画出这几个选项在编辑器里的样子：过程宏展开后生成的代码、关掉构建脚本后 `OUT_DIR` 里的代码无法解析、文档注释里的代码是否着色、保存时检查报告编译器警告还是 Clippy 的 lint。
- 「构建工具 › Cargo」页画出 Lithe 查找 cargo 的顺序（项目环境、全局默认、自动发现）和 rustup 选 Rust 版本的顺序。
- 改了还没应用的选项会先在预览里显示，并标出“含未应用的修改”。预览跟随界面语言和浅色、深色外观；设置窗口变宽时卡片放得下就两张一行。

已知限制：
- 还不能设置传给 rust-analyzer 的环境变量和 rustfmt 的额外参数，标准库路径也还没有显示。
- 预览画的是示例代码，不是当前项目的代码。
- Windows 上代码的字距比 Lithe 自己画的略宽：预览按 SF Mono 的字宽排版代码，标记才能对准字符。

验证：
- 在 macOS 上跑宿主端到端测试：后端由宿主启动，两个预览在中英文下都画出、通过 Core 校验，草稿会改变预览，窗口变宽后按新宽度重画，插件安装目录不被写入；原有的构建、调试和新建项目测试也都通过。
- 用宿主无头界面截图检查了中英文、浅色和深色外观、默认值和未应用的修改。
- Windows 包的后端只在 CI 里构建，还没有在 Windows 版 Lithe 里打开过；状态见 `docs/feature-matrix.md`。

权限：新增 `ui.contribute`（在设置页显示预览）。

兼容性：
- 需要 Lithe 桌面端 0.8.12 或更新版本，和 0.1.0 相同。
- 发布包按平台分开：`-darwin.zip`（Apple Silicon 和 Intel 通用）、`-windows-x64.zip`、`-windows-arm64.zip`。
